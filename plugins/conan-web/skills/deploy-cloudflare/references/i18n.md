# 다국어 정적 사이트 점검

기준: 2026-11 PixelUp(Next.js 정적 내보내기)을 영어 기본 + 한국어(`/ko`)로 바꾼 경험. 글로벌 대상 서비스는 처음부터 이 구조로 시작하는 편이 옮기는 비용이 적다.

## 주소 구조

- 기본 언어(글로벌 대상이면 영어)는 접두어 없이 `/`, 나머지 언어는 `/<언어 코드>/...`에 둔다. 페이지마다 언어별 주소가 하나씩 있고 slug는 언어와 관계없이 같게 둔다(언어 버전끼리 짝을 맞추기 쉽다).
- 브라우저 언어로 **자동 이동시키지 않는다.** 구글 크롤러는 영어 브라우저로 동작하므로, 자동 이동이 있으면 다른 언어 페이지를 색인하지 못한다. 대신 브라우저 언어와 페이지 언어가 다를 때 안내 띠를 띄우고, 고른 언어를 `localStorage`에 기억한다.
- 헤더에 같은 페이지의 다른 언어로 가는 링크를 둔다.

## 페이지마다 확인할 것

| 항목 | 기준 |
|---|---|
| `<html lang>` | 페이지 언어와 같음. Next.js App Router는 루트 레이아웃이 하나면 모든 페이지가 같은 lang이 되므로 route group으로 언어마다 루트 레이아웃을 둔다(`app/(en)/layout.tsx`, `app/(intl)/[locale]/layout.tsx`). |
| canonical | 그 언어의 주소 자신 |
| hreflang | 모든 언어 + `x-default`(기본 언어 주소). 자기 자신도 포함 |
| 메타데이터 | title, description, OG `locale`(`en_US`, `ko_KR`)과 `alternateLocale`이 그 언어 |
| JSON-LD | `inLanguage`가 그 언어, 가격 통화는 글로벌이면 USD |
| 내부 링크 | 그 언어의 접두어가 붙은 주소 |
| 404 | 루트 레이아웃이 여러 개면 Next.js 15.4+의 `app/global-not-found.tsx`(`experimental.globalNotFound`)로 모든 언어 문구를 한 페이지에 둔다 |

## 사이트맵과 robots

- `sitemap.xml`에 모든 언어 주소를 넣고, 각 `<url>`에 `xhtml:link rel="alternate" hreflang=...`을 붙인다(Next.js `MetadataRoute.Sitemap`의 `alternates.languages`).
- robots.txt의 `Sitemap:`은 하나면 된다.

## 콘텐츠

- 정책 페이지(개인정보처리방침, 약관)는 모든 언어로 둔다. 준거법이 한국이면 약관에 "언어 버전이 다르면 한국어판이 우선"을 적는다.
- 언어 선택을 `localStorage`에 저장하면 개인정보처리방침에 적는다.
- 운영자 이름 같은 환경 변수는 모든 언어 페이지에 나오므로 영어로 둔다.
- 짧은 UI 문구는 기본 언어 파일을 기준 타입으로 두고 다른 언어 파일이 같은 모양을 따르게 하면, 빠진 문구를 타입 검사가 잡는다.
- 워커·라이브러리의 오류는 문구 대신 이유 코드로 넘기고, 화면에서 그 언어 문구로 바꾼다.

## 확인 방법

1. 빌드 결과의 모든 HTML에서 `<html lang>`, canonical, hreflang 세 가지를 스크립트로 전수 확인한다. 기본 언어 페이지에 다른 언어 문자가 남았는지도 센다(언어 전환 버튼의 언어 이름은 예외).
2. `register-search`의 `check_search.py`로 배포된 홈의 lang·hreflang·사이트맵 alternates를 본다.
3. 브라우저에서 `navigator.languages`가 다른 상태로 안내 띠, 전환, 선택 기억을 확인한다.
4. 배포 뒤 서치 콘솔·서치어드바이저에 사이트맵을 다시 제출한다.
