# GA4 콘솔 화면 순서 (Claude in Chrome 또는 앱 안의 브라우저)

기준: 2026-11 PixelUp 연결 때의 한국어 GA 화면. 구글이 화면을 자주 바꾸므로 문구가 다르면 비슷한 메뉴를 찾는다.

## 시작 전

- Claude in Chrome 도구를 쓰기 전에 `anthropic-skills:chrome-browser` 스킬의 안내(탭 확인, 새 탭에서 작업, 끝나면 탭 닫기)를 따른다.
- 화면 조작은 스크린샷 좌표 클릭보다 `find`로 요소를 찾아 `ref`로 누르는 쪽이 덜 틀린다. 드롭다운 항목, 표의 행처럼 위치가 바뀌는 것은 특히 그렇다.
- 여러 단계를 미리 알 수 있으면 `browser_batch`로 묶어 왕복을 줄인다.
- **사용자가 속성을 직접 만들겠다고 할 수도 있다.** "다른 프로젝트처럼 GA 붙여 줘"라는 요청이면, 에이전트가 브라우저로 만들지 사용자가 만들고 측정 ID만 알려 줄지 처음 질문에 함께 넣는다.

### 앱 안의 브라우저(Claude_Browser)로 할 때

Claude in Chrome이 연결되지 않으면(두 번 시도해도 "not connected", `list_connected_browsers`가 `[]`) 더 시도하지 말고 데스크톱 앱 안의 브라우저를 쓴다. GA·서치 콘솔은 이 브라우저에서 잘 동작했다(2026-11-20).

1. `preview_start`에 `url`을 주어 GA 관리 화면을 연다. 새 패널은 구글에 로그인되어 있지 않아 accounts.google.com이 나온다. 비밀번호와 2단계 인증은 대신 입력하지 않으므로, 사용자에게 그 패널에서 로그인하라고 하고 "로그인했어"를 기다린다. 한 번 로그인하면 그 패널에 남는다.
2. 기본 패널은 폭이 좁아(약 800px) GA의 탭과 표가 접힌다. `resize_window`로 1400×900쯤으로 넓히고, 끝나면 `preset: "desktop"`으로 되돌린다.
3. 좌표로 누르려면 직전에 `computer` 동작의 `screenshot`이 있어야 한다. 스크린샷 크기와 실제 화면 크기가 다를 수 있으므로 좌표보다 `find` → `ref` 클릭을 쓴다. `find`에는 화면에 보이는 한국어 이름을 그대로 넣는다("저장 버튼"처럼 설명을 붙이면 못 찾는 경우가 많다).
4. 패널을 띄우거나 다른 주소로 이동한 직후에 `javascript_tool`을 실행하면 "정책을 확인하는 중"이라는 답만 돌아오기도 한다. 그러면 잠시 뒤 다시 실행한다.

## 1. 계정

1. `https://analytics.google.com/analytics/web/`를 연다.
   - "Google 애널리틱스에 오신 것을 환영합니다 / 측정 시작" 화면이면 **이 구글 계정에는 GA가 없다**는 뜻이다. 바로 만들지 말고 계정부터 확인한다.
2. 오른쪽 위 프로필 아이콘을 눌러 로그인된 계정 목록을 본다. 어느 계정에 만들지 사용자에게 묻는다(AskUserQuestion). 다른 사이트의 GA가 있는 계정이 보통 맞다.
3. 계정을 바꿀 때는 `https://analytics.google.com/analytics/web/?authuser=<email>`로 이동한다. 홈 주소가 `#/a<계정ID>p<속성ID>/...` 형태로 바뀌면 GA가 있는 계정이다.
4. 메뉴 계정을 잘못 고르면 엉뚱한 계정에 속성이 생긴다. 만들기 전에 화면 왼쪽 위의 "모든 계정 > <계정 이름>"을 확인한다.

## 2. 속성 만들기

1. 관리(왼쪽 아래 톱니바퀴) → 왼쪽 위 **+ 만들기 → 속성**. 주소로 가려면 `#/a<계정ID>p<아무 속성ID>/admin` 후 만들기.
2. **속성 만들기**: 속성 이름(서비스 이름), 보고 시간대 국가 "대한민국"(드롭다운의 검색칸에 입력) → 시간대가 (GMT+09:00)으로 바뀌는지 확인, 통화(애드센스 수익은 달러로 오므로 미국 달러로 둬도 됨) → 다음.
3. **비즈니스 세부정보**: 업종 카테고리(웹 도구는 "인터넷 및 통신"), 규모(1인·소규모는 "작음") → 다음.
4. **비즈니스 목표**: 정보성 웹 도구는 "웹 또는 앱 트래픽 파악", "사용자 참여 발생 시간 및 유지율 보기" 두 개. 판매·리드는 해당할 때만 → **만들기**.
   - 기존 GA 계정에 속성을 추가할 때는 약관 동의 화면이 나오지 않는다. 새 GA 계정을 만드는 경우에만 데이터 공유 설정과 약관이 나오며, 이것은 사용자가 직접 확인한다.

## 3. 웹 스트림

1. **데이터 수집 시작하기 → 웹**.
2. 웹사이트 URL: 프로토콜은 `https://`로 두고 주소만 입력(`pixelup-ai.pages.dev`). 스트림 이름: "<서비스> 웹".
3. **향상된 측정** 톱니바퀴 → 항목별 스위치:

   | 항목 | 권장 | 이유 |
   |---|---|---|
   | 페이지 조회 | 켬(끌 수 없음) | 기본 |
   | 스크롤 | 켬 | 개인 정보 없음 |
   | 이탈 클릭 | 켬 | 외부 링크 주소만 |
   | 사이트 검색 | 사이트 안 검색이 없으면 끔 | 검색어가 개인 정보일 수 있음 |
   | 양식 상호작용 | **끔** | 양식 이름·ID를 보냄. 파일 선택 입력도 양식으로 잡힐 수 있음 |
   | 동영상 참여 | 상관없음 | 유튜브 삽입이 없으면 이벤트도 없음 |
   | 파일 다운로드 | **끔** | `file_name`, `link_url`을 보냄. 결과 파일을 내려받는 도구라면 파일 이름이 나갈 수 있음 |

   오른쪽 위 **저장** → **만들고 계속하기**.
4. 만든 뒤 "Google 태그" 설치 안내 창이 뜨면 닫는다(코드에 이미 gtag가 있으므로 필요 없음). "이러한 설정에 대한 액세스 권한" 같은 빈 창이 떠도 닫으면 된다.
5. **다음 → 홈으로 이동**. 홈 주소에서 새 속성 ID(`p<숫자>`)를 확인해 둔다.

## 4. 속성 설정 마무리

1. **데이터 보관**: 관리 → 데이터 수집 및 수정 → **데이터 보관**(주소 `#/a<계정ID>p<속성ID>/admin/datapolicies/dataretention`) → "이벤트 데이터"의 보관 기간을 "14개월"로 바꾸고 저장(방침과 맞춤). "사용자 데이터"는 이미 14개월인 경우가 많으니 이벤트 데이터 쪽을 바꾸는 것이다. 저장 후 페이지를 다시 불러와 값이 남았는지 확인한다.
2. **맞춤 측정기준**: 관리 → 데이터 표시 → **맞춤 정의** → 맞춤 측정기준 만들기. 측정기준 이름(한국어로 알아보기 쉽게), 범위 "이벤트", 이벤트 매개변수(코드의 이름 그대로, 예: `backend`) → 저장. 숫자 값(처리 시간 `seconds` 등)은 맞춤 측정항목으로 만든다.
   - 먼저 이미 등록된 목록을 읽고(`get_page_text`) 빠진 것만 만든다.
   - 매개변수 칸은 입력하는 동안 **비슷한 다른 이름을 제안한다**(`from`을 넣자 링크 클릭 이벤트의 `from_page`를 띄웠다). 제안을 고르지 않는다. 코드에서 정확한 이름을 먼저 찾고(`grep -rn "<이벤트 이름>" components lib src`), 그대로 입력한 뒤 제안 목록만 닫고 저장한다.
   - 만들기 창은 오른쪽에서 열리는 패널이다. 안의 입력란과 저장 버튼은 `find "dialog"`로 창을 찾은 뒤 `read_page`(그 `ref_id`, `filter: interactive`)로 읽어 `ref`로 누른다. 저장 버튼은 창 오른쪽 위에 있고 이름이 비어 있어 `find "저장"`으로는 안 잡힌다.
   - 여러 개를 이어서 등록했으면 마지막에 목록을 다시 읽어 개수("N개 중 1~N번째")와 이름을 확인한다. 저장이 조용히 실패한 경우가 있었다(이름에 `·`를 넣은 두 개). 저장 직후 첫 읽기에는 새 줄이 안 보일 수 있으니 한 번 더 읽는다.
3. **페이지 변경 측정**: 데이터 스트림 → 향상된 측정 톱니바퀴 → 페이지 조회 "고급 설정 표시" → "브라우저 기록 이벤트 기반 페이지 변경"이 켜져 있는지 확인.

## 5. 측정 ID

1. `#/a<계정ID>p<새 속성ID>/admin/streams/table/` → 스트림 행을 누르면 "웹 스트림 세부정보" 창이 열린다.
2. 측정 ID를 페이지 텍스트에서 뽑는다(스크린샷 글꼴은 0과 O가 비슷하다).
   ```js
   (document.body.innerText.match(/G-[A-Z0-9]{8,12}/g) || []).join(',')
   ```
   헷갈리면 글자 코드를 본다: `[...id].map(c => c + ':' + c.charCodeAt(0))` (숫자 0은 48, 영문 O는 79).
3. 스트림 세부정보 상단의 "데이터 수집이 활성화되어 있지 않습니다" 경고는 배포 후 첫 방문이 들어오면 사라진다.

## 6. 실시간 확인

- 실시간 개요: `https://analytics.google.com/analytics/web/?authuser=<email>#/a<계정ID>p<속성ID>/realtime/overview`
- 사이트를 Chrome에서 한 페이지 연 뒤 1~2분 안에 "페이지 제목 및 화면 이름별 조회수"에 그 페이지가 나오면 연결된 것이다. 페이지에서 `typeof gtag`, `dataLayer.length`, `gtag/js?id=` 스크립트 존재를 함께 확인하면 원인을 좁히기 쉽다.

## 7. 자주 쓰는 화면 주소

`https://analytics.google.com/analytics/web/?authuser=<email>#/a<계정ID>p<속성ID>/` 뒤에 붙인다.

| 화면 | 경로 |
|---|---|
| 이벤트(주요 이벤트·최근 활동 탭) | `admin/events/hub` |
| 맞춤 정의 | `admin/customdefinitions/hub` |
| 데이터 보관 | `admin/datapolicies/dataretention` |
| 데이터 스트림 | `admin/streams/table/` |
| 실시간 | `realtime/overview` |
| 탐색 분석 | 경로가 다르다: `#/analysis/a<계정ID>p<속성ID>` |

주소로 바로 가면 가끔 홈 화면으로 돌아간다(2026-11 맞춤 정의). 그러면 관리 화면 왼쪽 메뉴에서 항목을 눌러 들어간다.

## 8. 유입경로 탐색 만들기

**데이터가 없어도 만들 수 있다.** 단계의 이벤트를 고를 때 GA가 아직 받지 않은 이름을 입력하면 목록에 `이벤트 생성: "<이름>"` 줄이 나오고, 그것을 고르면 된다.

1. 왼쪽 아이콘 메뉴의 **탐색** → 처음이면 안내 풍선을 닫는다 → **유입경로 탐색 분석**.
2. 왼쪽 "변수"의 탐색 분석 이름을 알아보기 쉽게 바꾼다(예: "방문에서 다운로드까지"). 이름 칸을 누르고 전체 선택한 뒤 새 이름을 입력하고 Enter를 누른다.
3. "설정"의 단계 옆 연필(`find "유입경로 단계 수정"`) → 단계 편집 창.
4. 기본 초안은 3단계(처음 열 때/방문, 화면/페이지 조회, 구매)다. 필요 없는 단계는 단계 메뉴(⋮) → **삭제 단계**, 필요 없는 조건은 "필터에서 이 조건 삭제"로 지운다.
5. 단계마다: 이름 칸에 이름, 이벤트 칸(`필터링 기준으로 삼을 개념 선택`)을 눌러 검색칸에 이벤트 이름을 입력하고 결과 줄을 고른다. 한 단계에 이벤트 둘을 허용하려면 **또는** → **새 조건 추가**(예: `download` 또는 `zip_download`).
6. **단계 추가**로 단계를 늘린다. 새 단계 이름 칸에는 "새 단계"가 미리 들어 있어 입력한 글자가 뒤에 붙는다. 이름 칸을 누른 뒤 전체 선택하고 입력한다.
7. 편집할 때마다 화면이 다시 그려져 앞서 찾은 `ref`가 무효가 된다("ref is stale"). 누르기 전에 `find`나 `read_page`로 다시 찾는다.
8. **적용하기** 전에 단계 이름을 스크립트로 한 번에 확인한다: `[...document.querySelectorAll('input[placeholder="이름"]')].map(i => i.value)`
9. 적용하면 저장된다. 보고할 때 첫 숫자(예: 방문 20명 중 2명이 이미지 추가, 확대 시작 0명)와 아직 데이터가 없는 단계를 함께 알려 준다.

예: PixelUp 5단계 = 방문(`session_start`) → 이미지 추가(`add_images`) → 확대 시작(`upscale_start`) → 확대 완료(`upscale_done`) → 다운로드(`download` 또는 `zip_download`).
