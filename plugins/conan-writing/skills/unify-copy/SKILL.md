# unify-copy: 한 문서의 말투를 하나로

문서마다 말투는 다를 수 있다. 하지만 **한 문서 안에서는 말투가 하나여야 한다.** 한 카드 설명이 "~크다"로 끝나고 옆 카드가 "~합니다"로 끝나면, 내용이 좋아도 문서가 제멋대로 쓴 것처럼 보인다. 이 스킬은 문구를 종류별로 나눠 각각 정한 형태로 맞춘다.

## 0단계 · 말투를 고르게 한다

처음에 사용자에게 묻는다. 질문 도구가 있으면 그것으로 묻고, 선택지마다 이 문서에 적용한 예를 하나씩 붙인다. 추천 답은 맨 앞에 두고, 문서에서 가장 많이 쓰인 형태를 추천한다(바꿀 곳이 가장 적다).

| 질문 | 선택지 |
|---|---|
| 설명 문장의 종결 | ~합니다 / ~한다 / ~해요 / 개조식(단어나 "~함"으로 끝냄) |
| 짧은 문구의 형태 | 단어형 / 서술형 |
| 최고 위계 제목도 맞출지 | 제외 / 포함 |

- 원문 인용은 묻지 않고 항상 그대로 둔다. 다른 문서의 문장을 옮긴 것이라 말투를 바꾸면 인용이 아니게 된다.
- 사용자가 이미 말투를 정해 주었으면 묻지 않고 그대로 쓴다.
- 물을 사람이 없으면 추천 답으로 진행하고, 무엇을 골랐는지 결과 앞에 한 줄로 적는다.

## 1단계 · 문구를 세 종류로 나눠 모은다

문서의 문구를 빠짐없이 모아 세 종류로 나눈다. 장(페이지)과 자리를 함께 적는다.

| 종류 | 들어가는 것 | 처리 |
|---|---|---|
| 짧은 문구 | 소제목, 카드·칸 제목, 라벨, 표 머리글, 단계 이름, 버튼 | 2단계 A |
| 설명 문장 | 카드 설명, 리드 문장, 캡션, 각주, 발표자 노트 | 2단계 B |
| 손대지 않는 것 | 원문 인용, 최고 위계 제목(제외를 고른 경우), 고유 명사 | 목록에만 표시 |

**최고 위계 제목**은 위치가 아니라 위계로 판단한다. 글자가 가장 크고 그 페이지의 메시지를 말하는 제목이다. 그 위에 작게 붙는 섹션 라벨은 짧은 문구다.

**대상은 화면에 보이는 글자와 발표자 노트다.** 이미지 대체 텍스트(alt), 파일 메타데이터, 코드 주석은 모으지 않는다.

**마침표로 끝나는 완결 문장은 자리가 어디든 설명 문장으로 본다.** 인용 상자나 핵심 문구 자리에 있어도 문장이면 설명 문장 규칙(B)을 따르고, 짧은 문구로 줄이지 않는다. 굵게 쓴 첫 문장이 카드 제목 역할을 해도 마침표가 있는 문장이면 같다.

**원문 인용**은 따옴표, 인용 상자, "원문" 표기처럼 다른 문서에서 옮겼다는 표시가 있는 문장이다. 표시가 없어 애매하면 사용자에게 한 줄로 확인한다.

## 2단계 · 종류별 규칙으로 고친다

### A. 짧은 문구

1. **같은 자리의 문구는 모든 장에서 같은 형태로 맞춘다.** 한 장의 소제목이 "팀별로 만드는 문서"(명사구)이고 다른 장의 같은 자리가 "이렇게 설계했습니다"(서술형)이면 어긋난 것이다.
2. **단어형을 골랐으면 단어로 끝낸다.** 꾸밈 단어 뒤에 행위나 대상을 나타내는 명사(입력·작성·확인·안내·선택·검토·문서·기준)를 둔다.
   - 조사로 끝내지 않는다: "입력은 한 문장으로" → "한 문장 입력". "~으로", "~만", "~까지"로 끝나면 서술어가 잘린 문장이다.
   - "~하기"로 끝내지 않는다: "아는 내용만 더 적기" → "추가 정보 입력".
   - 관형절을 단어로 줄인다: "팀별로 만드는 문서" → "팀별 문서", "걸리는 시간" → "소요 시간".
   - 같은 자리끼리 단어 수와 구조를 비슷하게 맞춘다: 한 문장 입력 / 추가 정보 입력 / 진행 과정 안내 / 소요 시간 안내.
   - **나란히 놓인 같은 종류의 이름은 끝 단어를 하나로 맞춘다.** 사전대로 바꾸면 "사업기획서 작성 / 스펙 생성"처럼 갈릴 수 있다. 원문이 "쓰기 / 만들기"로 갈려 있어도, 같은 표·같은 목록 안이면 "사업기획서 작성 / 스펙 작성"처럼 하나로 맞춘다.
3. **표기를 맞춘다.** 물음표 유무, "·" 구분, 마침표 유무를 같은 자리끼리 통일한다. 짧은 문구에는 마침표를 찍지 않는다.
4. 바꾼 단어가 이웃 라벨과 똑같아지면(라벨 "상태별 화면" 아래 제목도 "상태별 화면") 다른 단어를 고른다.

### B. 설명 문장

1. **문장마다 종결 어미를 확인한다.** 카드 하나, 문단 하나 안에서도 "~크다"와 "~합니다"가 섞이면 안 된다. 0단계에서 고른 종결로 모두 바꾼다.
2. **같은 묶음 안에서는 마침표 유무를 맞춘다.** 완결 문장이면 마침표를 찍는다. 목록처럼 "조사 · 역할별로 나눠 모읍니다"가 이어지는 묶음은 모두 찍거나 모두 빼되, 한 묶음 안에서 섞지 않는다.
3. **같은 자리의 설명은 문장 수와 길이를 맞춘다.** 나란히 놓인 카드 세 장의 설명이 한 문장, 세 문장, 두 문장이면 하나가 비어 보이거나 넘쳐 보인다. 가장 흔한 문장 수에 맞춘다.
4. **문장 안에서 늘어진 표현을 단어로 줄인다.** 문장은 끝까지 완결하되, 그 안의 군더더기만 줄인다.
   - "~하는 것이 가능합니다", "~할 수 있습니다" 남발 → "~합니다"
   - "~를 통해" → "~로", "~에 대해" → 빼거나 "~를"
   - "~하는 일이 줄어듭니다"처럼 명사로 바꿀 수 있는 덩어리 → 단어 사전(C)의 단어로
5. **개조식을 골랐으면** 문장 대신 "단어 + 단어"나 "~함"으로 끝낸다. 한 카드 안에서 개조식과 문장을 섞지 않는다.
   - 예: "기획서를 읽고 브라우저에서 바로 열리는 화면이 나옵니다. 디자이너는 다듬는 일부터 시작합니다." → "기획서 기반 HTML 화면 생성 · 디자이너는 보완부터 시작". 앞은 단어, 뒤는 "~함"처럼 끝맺음이 갈리지 않게 한다.
6. **뜻은 바꾸지 않는다.** 이 스킬은 끝맺음과 단어만 바꾼다.
   - 문장을 대구나 짧은 문구로 압축하지 않는다. "형식은 minuet이 알고 있습니다. 사용자는 키워드와 간단한 설명만 주면 됩니다."를 "형식은 minuet, 키워드는 사용자"로 줄이면 "간단한 설명"이라는 뜻이 빠진다. 압축이 필요해 보이면 distill-headline 후보로 따로 제안한다.
   - 말투를 맞추다가 내용을 더하거나 빼야 할 것 같으면 바꾸지 말고 사용자에게 따로 알린다.

### C. 단어 바꿈 사전 (A와 B 모두)

동사를 단어로 바꿀 때는 `reference/word-map.md`의 짝을 쓴다. 쓰기 → 작성, 만들기 → 생성, 고르기 → 선택, 적기 → 입력, 읽기 → 확인처럼 뜻이 정확한 한자어 명사를 고르되, 처음 보는 사람이 바로 알아듣는 흔한 단어만 쓴다.

- **뜻의 세기를 유지한다.** "급히 그리는 일" → "급조"처럼 부정적인 뜻이 더해지거나, "도와준다" → "보장한다"처럼 약속이 커지는 단어는 고르지 않는다. 맞는 단어가 없으면 원래 표현을 둔다.
- **단어를 바꾸면 뒤에 붙은 조사를 받침에 맞게 고친다.** "아이디어 제안받기는"을 "아이디어 제안"으로 바꾸면 "아이디어 제안은"이 되어야 한다. 받침이 생기거나 없어지면 은/는, 이/가, 을/를, 와/과, 으로/로가 바뀐다. 이름을 문서 전체에서 한꺼번에 바꿀 때 특히 발표자 노트나 본문 문장 속에 들어간 이름을 놓치기 쉽다.
- 문서 안의 이름이 실제 제품·스킬 이름과 달라져도 괜찮다. 문서의 말투를 우선한다. 다만 화면 캡처 안의 글자와 바로 옆에 놓이면 사용자에게 한 줄로 알린다.

## 3단계 · 바꿀 안을 보여 주고 승인받는다

장별로 표를 만든다. 바꾸지 않는 문구는 넣지 않는다.

| 장 | 자리 | 지금 | 바꾼 뒤 | 이유 |
|---|---|---|---|---|

- 표 위에 0단계에서 정한 말투와, 손대지 않는 것(원문 인용 등)의 개수를 한 줄로 적는다.
- 사용자가 "채팅으로만"이라고 하면 표만 보여 주고 끝낸다.
- 승인을 받은 뒤에 파일을 고친다. 일부만 승인하면 그 부분만 고친다.

## 4단계 · 적용하고 다시 검사한다

1. 고친 뒤 1단계를 다시 해서, 종류마다 형태가 섞인 곳이 0건인지 확인한다. 남은 곳이 있으면 목록으로 보여 준다.
2. **바꾼 단어 바로 뒤의 조사를 모두 확인한다.** 바꾼 단어마다 문서 전체에서 "바꾼 단어 + 조사"를 찾아, 받침과 맞지 않는 조합(예: "작성는", "제안를", "입력가")이 0건인지 본다. 일괄 바꾸기를 했다면 이 확인을 빼먹지 않는다.
3. 슬라이드나 고정 크기 화면이면 글자가 넘치지 않는지 확인한다. 단어형으로 바꾸면 대개 짧아지지만, 설명 문장의 종결을 바꾸면 길어질 수 있다.
4. 결과를 짧게 보고한다: 바꾼 문구 수(종류별), 손대지 않은 것, 사용자가 판단할 남은 문제.

## 다른 스킬과 나누는 일

- **distill-headline**: 제목·소제목의 **내용**을 목적까지 끌어올린다. 이 스킬은 **형태**만 맞춘다. 제목 후보를 새로 지을 때는 distill-headline을 쓰고, 고른 후보의 끝맺음은 이 스킬의 규칙에 맞춘다.
- 둘을 함께 쓸 때는 distill-headline으로 제목 내용을 먼저 정하고, 이 스킬로 문서 전체 말투를 맞춘다. 순서를 바꾸면 제목을 고친 뒤 말투를 다시 맞춰야 한다.
